## 入口

当用户说“微信客服”“看下微信有没有客户找我”“帮我回微信客户”时用这份技能。
只在微信里做客服，不主动加好友、不群发、不做营销。

## 步骤

1. 先读屏，列出未读会话：会话名、最后一条客户原话、时间。一次只处理一个会话，处理完再下一个。
2. 给每条客户问题分类：咨询 / 下单 / 物流 / 售后 / 投诉 / 价格与优惠 / 账号与付款 / 其他。
3. 只用 FAQ 模板里写明的内容回答。FAQ 里没有的，不编价格、库存、发货时间、退款结果，写成“待确认”。
4. 起草回复，原文展示给用户，写明依据的是 FAQ 哪一条、客户原话是什么。
5. 用户明确说“发”之后，才在微信里点发送。用户没说发，就只停在起草。
6. 发完后读回一次，确认发出的是起草的那段文字、发到了正确的会话，再向用户汇报结果。

## 容易出错的地方

- 同名、头像相似的会话最容易发错人：发送前必须核对会话名和最后一条客户原话。
- 客户一次发多条消息时，先读完一个会话的全部未读再起草，不要只回第一条。
- 微信里一次只能一个任务用同一个 App，多个客户要排队，不要并行抢同一个 App。
- 付款、输密码、验证码页面不要代操作，交给用户处理。

## 怎样算办成（核实证据）

- 汇总：列出的会话、原话、时间与屏上看到的一致。
- 起草：每句关键事实都能在 FAQ 模板里找到对应条目，找不到的标“待确认”。
- 发送：发送后读回的已发消息与起草文本一致，且在正确的会话里。

## 什么时候停下交给用户

- 涉及退款、改单、补发、赔偿、价格优惠、承诺发货或到货时间时，停下，只起草建议，不直接发送。
- 客户投诉、情绪激烈、提到消协 / 投诉 / 律师、要求人工时，停下，汇总原话交给用户。
- 客户发了手机号、地址、订单号、支付信息时，不要在回复里复述完整信息，汇总时做脱敏，只留后几位或订单尾号。
- 读不到、发不出去、微信提示异常或要验证时，停下，不要反复重试。
- 用户没有确认就不要发送；用户说“先不发”“等等”时，立即停下。
